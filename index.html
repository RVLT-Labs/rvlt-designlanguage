Foundations

A production company's software should feel made by a live-events crew, not generated from a template.

Dark first, warm

Espresso is the primary surface; Paper is the opt-in alternate. Depth is a luminance ladder (paper, paper-2, card, elev), never a glow.

The dial

Marketing sits at the expressive end. Apps sit at the functional end: calm data, fun chrome. Personality goes into empty states, toasts, the sidebar and success moments, never onto the data.

The spotlight rule

About 90% of a dark viewport stays in the espresso ramp. Brightness is spent as at most three lit objects per page, two on a phone.

Physical edges

A 2px outline and a hard offset shadow, like flight-case labels and enamel patches. No soft blur except the two sanctioned marketing floats.

One red, three roles

Core red (#E0363D / #C12229, locked) draws the mark, rings and strokes. --action-red fills anything with white text. --red-text draws red words. Never decoration, never a module, avatar, department or chart colour.

Field first

Phones on the dock, gloves, sun and dead spots. 44px targets (48px for scan and confirm), labels above fields, status always carries a word, offline is honest, motion honours reduced-motion completely.

Voice

A production manager, not a marketer: trade words, concrete numbers, dry wit, no fake logos or testimonials. Plain words in alerts, conflicts and destructive confirmations.

Contrast is a contract

Every text, pill, fill and control boundary is a role on a surface, verified in both themes. There are no accepted exceptions; --faint is never text.

Generated from packages/flow-theme/tokens.json (the canonical values). Components reference tokens, never raw values; install them with @import "@rvlt/flow-theme/globals.css".

Product layers

Both products run on the same tokens, type, voice and states. These differences are deliberate, and the only places a product departs from the core (DESIGN.md §19).

RVLT Flow: production operations

  • Pill buttons with the hard red-700 drop.
  • Module hues for wayfinding: Projects blue, Assets amber, Crew purple, Schedule green, Maintenance coral, Warehouse teal. Active items keep an ink label; the hue carries the icon and indicator.
  • The stage-light mascot in empty states; Albert for RVLT-wide moments.
  • Phone: bottom tab bar, scan action in the thumb zone, scheduler as an agenda.

RVLT Binder: the prompt corner

  • Rounded-rectangle buttons (30px desktop, 44px phone).
  • The script page is always white paper, in both themes, on a dark stage.
  • Department colour is the only colour on the page, and it draws marks: outline, leader, dash. Abbreviations and numbers stay page ink.
  • Markup and Calling draw the page identically; offline is a muted state, never red.

Using and building

Install the theme

npm i @rvlt/flow-theme tw-animate-css, then in app/globals.css:

@import "tailwindcss";
@import "tw-animate-css";
@import "@rvlt/flow-theme/fonts.css";
@import "@rvlt/flow-theme/globals.css";

Add components

With the shadcn CLI from this site's registry, for example npx shadcn@latest add https://rvlt-labs.github.io/rvlt-designlanguage/r/field.json. Restyle stock shadcn through the role aliases, never raw hex.

Change a token

Edit tokens.json, mirror Appendix A, §15.1 and design-system/tokens.json, run build-css.mjs, then npm test. The contrast guard fails if any allowed pairing drops below AA.

Before you ship

Run the self-audits: §15.3 for app screens, §16.15 for anything responsive, §12 for marketing. Check reduced motion, 44px targets, labels and status words.
